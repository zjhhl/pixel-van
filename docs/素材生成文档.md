# 像素方块小车游戏 — 素材生成文档

> 本文档写给负责生成素材的模型/画师。游戏代码由Claude编写（HTML5 Canvas，竖屏）。
> 所有 PNG 需透明背景；若生成模型不支持透明，可用纯白/纯绿背景并在文档标注，由代码端抠图。

---

## 0. 游戏画面构成（帮你在生成前理解用途）

```
┌─────────────────────┐
│                     │
│   像素画区域（大）   │  ← 由很多小方块(cube)拼成一幅像素画
│   28 × 36 格        │
│                     │
├─────────────────────┤
│ ▢ ▢ ▢ ▢ ▢  5个停车位 │  ← 待命小车，虚线框
├─────────────────────┤
│  车队（2~3排）       │  ← 点击派车去卸货
└─────────────────────┘
```

玩法：每辆车有颜色 + 数字（载货量）。点击小车 → 车开到像素画下方卸货点 →
方块一颗颗飞入同色未填格子 → 全部填满过关。

## 2. 小车（最高优先级）

**用途**：游戏主角。仿截图里的圆润面包车，伪 3D 立体感。

### 2.1 视角与状态

统一**后侧 45° 俯视角**（从车后上方看，车头朝远处/画面上方），和截图一致。

每色 2 张：

| 文件 | 状态 | 说明 |
|---|---|---|
| `vans/van_{色}_closed.png` | 停车/行驶 | 尾门关闭，正常车 |
| `vans/van_{色}_open.png` | 卸货中 | 尾门打开，露出同色货箱 |

### 2.2 颜色列表（9 色）

`white, black, red, orange, yellow, green, blue, purple, pink`

共 **18 张**。

### 2.3 生成要求

- 尺寸 **256×320**，车居中，占画面约 70%
- **车顶/引擎盖留浅色高光，车侧下部留深色阴影**（立体感关键）
- 车窗用深灰 `#2A2A2A`~`#3A3A3A`，不随车身变色
- 轮胎黑色 + 深灰轮毂，底盘带椭圆软阴影
- **不要画任何数字、文字、logo**（数字由代码动态叠加）
- 同一色的 closed / open 必须同角度同大小，仅尾门不同
- 9 个颜色尽量同一模板换色，形状比例完全一致

### 2.4 生成提示词模板（供参考）

```

3D render style, soft studio lighting, glossy plastic body,
{COLOR} body color, dark gray windows, black tires with hubcaps,
soft elliptical shadow under the car, plain white background,
no text, no numbers, no logo, centered, rear doors closed
```

open 状态把最后一句换成 `rear doors open showing {COLOR} cargo inside`。

## 7. 关卡底图（核心玩法数据）

**用途**：每关一幅像素画，代码把它按调色板拆成「颜色 → 需要的方块数」，并自动生成车队。

### 7.1 规格要求

- **实际像素即格子**：宽 24~32、高 32~40 像素（如 28×36），**1 像素 = 1 格**
- **必须 100% 填满**，不留透明/留白（天空、草地都是颜色）
- 只用第 1 节的 16 色调色板，**关闭抗锯齿/平滑**（或导出后用 nearest 放大检查）
- 主体居中、轮廓清晰，同类色块成片（碎色太多会导致车太多）

### 10.2 与文档原规格的差异（重要）

1. **小车视角改为「车后 3/4 视角」**，不是纯俯视。
   原因：纯俯视看不到尾门，"open 露出货箱"这个状态在俯视图里完全不可见，而它是卸货玩法的核心视觉反馈。
   现在的角度能看到尾门 + 车顶 + 右侧车身，9 色全部用同一张底图换色，**形状、大小、角度完全一致**。
2. **柔光投影已从图里去掉**。AI 底图的投影是糊在背景上的，抠图时无法保留干净边缘。
   建议代码端在画车时自绘一个椭圆投影（`ctx.ellipse` + 低透明度黑），效果更可控。
3. **白车 / 黑车的 open 状态辨识度偏低**（车身与尾门同色，靠内部开口区分）。
   建议代码端在 open 时额外给反馈：车顶闪一下、上方飘 "↓" 箭头、或载货数字归零动效。
4. **数字/文字全部空白**，车身中部与车顶都留了干净区域，代码叠数字不会压到细节。

### 10.3 关卡底图生成方式

AI 出图 → `tools/process_assets.py` 处理，流水线为：

1. 居中裁到目标宽高比（避免拉伸变形）
2. **全分辨率吸附到 16 色调色板**，再对每格取"众数"降采样
   （先缩放再量化会把心形的深红错吸成棕色，必须先量化后降采样）
3. 合并碎色块：占比 < 1.2% 的颜色并入相邻最多的颜色
   （否则会冒出几十个只有 1~2 格的色块，代码会生成一堆载货量 1 的小车）

### 11.3 关卡配色返工（重要）

第一批出来的关卡整体偏白、偏灰、偏暗，问题出在**量化的距离度量**上：

AI 生成的像素画用的是很"柔和"的配色（浅绿 `#80C070`、浅青 `#D0F0F0`），
而调色板里的 16 色是**鲜艳色**（green `#3FA34D`）。按 RGB 距离最近吸附时：

| 原图色 | 会被吸成 | 原因 |
|---|---|---|
| 浅绿 `#80C070` | **gray `#8A8A8A`** | 绿色分量不够高，反而离中性灰更近 |
| 浅青 `#D0F0F0` | **white `#FFFFFF`** | 饱和度过低 |

修法：量化前加一步 **HSV vibrance + gamma 提亮**（`_boost_for_palette`，参数 `gain=0.95, gamma=0.90`）：

```
s' = s * (1 + gain * (1 - s))      # 低饱和提得多、高饱和提得少
v' = v ** gamma                    # 整体提亮，纯黑轮廓 v=0 不受影响
```

效果：熊猫关背景从灰变回绿、樱花关粉红更饱满、巨龙关的龙终于看得清。
**这一步对"AI 柔和像素画 → 16 色硬调色板"是所有关卡都需要的。**

### 11.4 第二批踩的坑

1. **图标中心的"孔洞"抠不掉**。箭头/圆环类图标，中心与背景同色但被主体围住，
   不连通到画布边界，原来的 flood fill 抠不到，会留下一个灰块。
   → `remove_bg(global_thresh=True)`：不要求连通，所有接近背景色的像素一律抠掉。
   但容差必须比按钮小（图标 22~24，按钮 46），否则主体自身的浅色会被削成半透明。
2. **横幅的金色光晕不能用硬边抠图**，会把光晕切出一圈生硬的边。
   → `remove_bg_soft()`：alpha 随"与背景的色差"连续变化。
   再用饱和度削一次 alpha，把 AI 画在中心的那片低饱和灰米色变透明（本来就该留空给文字）。
3. **AI 图的右下角有半透明水印**，统一裁掉底部 7% 再处理。路面底图是平滑渐变，
   用局部像素水平外推填充，比裁切更不留痕。
4. **站牌那类"银灰主体 + 灰底"** 需要更高容差（50），否则柱子底部的投影会残留一圈拖影。
